# Web 首次管理员初始化设计

## 目标

机器人交付后，用户第一次打开 Web 控制台即可创建首个管理员，不需要执行 ROS 命令、进入 Python 虚拟环境或使用预设密码。

## 范围与安全边界

- 当认证数据库中没有任何用户时，控制台进入首次初始化模式。
- 初始化期间，同一局域网中任何能够访问控制台的人都可以提交首个管理员账号。
- 首个管理员创建成功后，初始化入口立即且永久关闭；后续账号只能由已登录管理员管理。
- 不增加一次性初始化码、物理确认、默认账号或默认密码。
- 所有控制台账号的密码最少为 6 个字符，包括首次初始化、管理员创建用户、修改密码和命令行维护入口。

## 后端接口

`GET /api/session` 在现有响应中增加布尔字段 `needs_setup`。认证数据库没有用户时为 `true`，否则为 `false`。

新增 `POST /api/setup`，请求体为：

```json
{
  "username": "admin",
  "password": "******",
  "password_confirmation": "******"
}
```

处理规则：

1. 用户名沿用现有非空、去除首尾空格及最大 64 字符规则。
2. 密码至少 6 个字符，且两次输入必须一致。
3. 后端必须在同一个数据库写事务中检查用户表为空并创建 `admin` 角色用户。
4. 并发初始化请求只能有一个成功；后续请求返回 HTTP 409。
5. 创建成功后建立与普通登录相同的会话，返回用户信息和 CSRF token，使浏览器直接进入控制台。
6. 参数无效返回 HTTP 400；已有用户时不泄露账号信息，只返回初始化已完成。

认证数据库增加原子方法负责“仅当用户表为空时创建管理员”。普通 `create_user` 不承担首次初始化并发控制。

## Web 界面

页面启动仍首先请求 `/api/session`：

- `needs_setup=true`：登录弹窗显示“初始化机器人控制台”，包含用户名、密码和确认密码；提交 `/api/setup`。
- `needs_setup=false` 且未登录：显示现有登录表单。
- 初始化成功：保存会话响应并直接加载控制台，不要求再次登录。
- 收到 409：提示其他访问者已经完成初始化，并切换回登录模式。

不增加独立 `/setup` 页面，避免额外路由和交付说明。

## 兼容性

- 保留 `krt_web_create_admin` 命令作为离线维护入口。
- 现有登录、会话、CSRF、角色和审计机制保持不变。
- 已有用户数据库升级后不会出现初始化界面。
- 密码最小长度由 10 调整为 6，已有密码哈希无需迁移。

## 测试与验收

自动测试覆盖：

- 空数据库的 session 返回 `needs_setup=true`。
- 首次初始化创建 admin、建立会话并返回 CSRF token。
- 用户名、6 位边界密码和确认密码校验。
- 已有用户时 session 返回 `needs_setup=false`，setup 返回 409。
- 两个并发初始化请求最多一个成功，数据库中只有一个管理员。
- 普通创建用户和修改密码统一接受 6 位、拒绝 5 位。
- 控制台模板在初始化与登录模式之间正确切换。
- 现有 Web API 测试继续通过。

人工验收使用全新临时数据库启动控制台，从浏览器完成首次管理员创建并直接进入控制台；刷新页面后只能看到普通登录流程。
